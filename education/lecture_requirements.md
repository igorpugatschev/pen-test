# Требования к лекциям курса

Этот документ фиксирует обновленный стандарт для всех уроков `education/lessons/`.

Главное требование: урок должен быть полноценной самостоятельной лекцией, а не списком тем, ссылок, книжных страниц или заданий “прочитать где-то еще”. Студент должен пройти урок без обращения к внешним источникам и получить достаточную теорию, примеры, практику и критерии сдачи внутри самого Markdown-файла.

## 1. Самодостаточность

Каждый урок обязан содержать весь минимально необходимый учебный материал:

- определения ключевых терминов;
- объяснение базовой модели или механизма;
- причинно-следственные связи: почему это работает именно так;
- ограничения и типичные ошибки;
- безопасные примеры команд, запросов, артефактов или сценариев;
- разбор ожидаемого вывода;
- проверку понимания;
- практику с критериями сдачи.

Недопустимый формат:

```markdown
Прочитайте страницы X-Y, выпишите термины, затем выполните практику.
```

Допустимый формат:

```markdown
Книги использованы как источники автора лекции. Ниже дана полная теория урока:
что такое shell, как shell ищет команду через PATH, почему which python3
нужен для воспроизводимости evidence, как это проверяется на macOS.
```

## 2. Роль книг

В курсе есть 5 книг, проиндексированных в `docs/socraticode/`. Они используются как база для подготовки лекций, но не заменяют лекцию.

Книги должны давать:

- системность объяснения;
- корректную терминологию;
- инженерные принципы;
- примеры, адаптированные в безопасный учебный формат;
- связь SDET-практики с Security QA.

Книги не должны использоваться как способ переложить обучение на студента. Раздел `Reading pack из книг курса` остается академическим следом и списком источников автора курса, а не обязательным внешним чтением для понимания базовой темы.

Формулировка, которую нужно использовать:

```markdown
Этот раздел не является заданием “пойди и найди теорию в книгах”.
Книги использованы автором курса для подготовки лекции, а студент получает
самодостаточное объяснение ниже.
```

## 3. Глубина лекции

Лекция должна давать не только “что нажать”, но и “как устроено”.

Для каждой темы нужно раскрывать:

- **модель:** из каких частей состоит механизм;
- **термины:** что означает каждое важное слово;
- **контекст:** зачем это нужно SDET/Security QA;
- **пример:** безопасная демонстрация на локальной цели, lab или разрешенном стенде;
- **вывод:** как читать фактический результат;
- **ошибки:** что обычно путает новичок;
- **границы:** что нельзя делать без approval;
- **переход:** как это знание понадобится в следующих уроках.

Пример для Linux-урока: недостаточно написать `Linux используется в пентесте`. Нужно объяснить уровни системы, kernel/user space, shell, `PATH`, пользователей, права, файловое дерево, stdout/stderr, где живут программы и почему среда влияет на результат.

Пример для web-урока: недостаточно перечислить HTTP-методы. Нужно объяснить request/response, headers, body, cookies, status codes, TLS boundary, cache, redirects, evidence и безопасные проверки в браузере/DevTools/Burp.

## 4. Обязательная структура урока

Каждый урок сохраняет текущие разделы:

- `## Учебная рамка`
- `## Reading pack из книг курса`
- `## Source-driven theory`
- `## Теория`
- `## Guided practice`
- `## Практическое занятие`
- `## Примеры вывода`
- `## Адаптация под macOS (M2, 8GB)`
- `## Задачи для самостоятельного выполнения`
- `## Частые ошибки`
- `## Вопросы на понимание`
- `## Практика на Slider AI`
- `## Rubric`
- `## Self-check`

Но разделы должны быть содержательными. Наличие заголовков не означает качество урока.

## 5. Требования к `Source-driven theory`

`Source-driven theory` не должен быть коротким конспектом или общим описанием.

Он должен:

- объяснять, какие идеи из книг превращены в лекционный материал;
- связывать тему с предыдущим SDET-опытом;
- отделять безопасную учебную интерпретацию от lab-only/offensive-техник;
- давать студенту рамку понимания перед подробной теорией.

Не допускается:

```markdown
Этот урок опирается на книги курса. Из источников берется работа с файлами.
```

Нужно:

```markdown
Из книги про PyCharm берем идею воспроизводимой рабочей среды:
инструмент существует в конкретной ОС, с конкретным путем и версией.
В Security QA это превращается в правило evidence: фиксировать OS,
architecture, tool path и tool version перед проверкой.
```

## 6. Требования к `Теория`

Раздел `Теория` является основной лекцией.

Минимальный стандарт:

- 6-12 содержательных подразделов для фундаментальных тем;
- таблицы для сравнения понятий, сред, статусов или команд;
- безопасные примеры;
- разбор “как читать результат”;
- объяснение типичных ошибок;
- связь с будущими уроками;
- отсутствие фраз “изучите самостоятельно”, если материал нужен для практики текущего урока.

Теория должна покрывать 100% концепций, которые требуются в практике этого же урока.

## 7. Требования к практике

Практика должна следовать лестнице:

1. **Минимум:** локальная безопасная операция, которую новичок может выполнить на macOS.
2. **Практика Slider AI:** только действия внутри `education/slider_ai_scope.md`; в ранних уроках это может быть подготовка scope/evidence без обращения к сайту.
3. **Углубление после изучения следующих уроков:** lab-only, Kali ARM64 VM, cloud lab или более сложный перенос после появления нужной теории.

Практика должна включать:

- точную среду выполнения;
- безопасную цель;
- команды или ручные шаги;
- ожидаемый вывод;
- интерпретацию результата;
- критерии остановки;
- что считается сдачей.

## 8. Требования к evidence

Каждый урок должен учить собирать evidence как инженерный артефакт.

Минимальный evidence отвечает на вопросы:

1. Где выполнялась проверка?
2. Какая цель была разрешена?
3. Что именно сделано?
4. Какой фактический результат получен?
5. Почему этот результат имеет значение?
6. Есть ли секреты или персональные данные?
7. Какой статус результата: `observation`, `finding`, `not reproducible`, `not applicable`, `requires approval`?

Evidence должен быть sanitized. Нельзя сохранять токены, cookies, пароли, приватные ключи, персональные данные и чужие секреты.

## 9. Требования к рабочей среде

MacBook Air M2 8GB используется как рабочая станция QA/пентестера.

Базовая логика:

- macOS native — обязательный безопасный путь новичка;
- Homebrew/official installers/`pipx`/`pip3` — установка на macOS;
- Kali Linux ARM64 VM — углубление или обоснованная Linux/Kali-среда;
- cloud lab — тяжелые сценарии, CTF, экзаменационная практика;
- `apt` — только для явно помеченной Kali/Linux-среды;
- x86/x64 VirtualBox VM не является базовым путем на Apple Silicon;
- VM на 8GB RAM ограничивать 3-4GB RAM и 2 CPU.

Каждая команда должна быть помечена средой, если есть риск спутать macOS и Linux.

## 10. Требования к Slider AI

Slider AI-практика должна быть профессиональной Security QA-практикой, а не “хакингом”.

Разрешенная цель:

```text
https://olddev.slider-ai.ru
```

Обязательные ограничения:

- production не тестируется;
- действия вне scope запрещены;
- DoS/load, brute force, destructive payloads, изменение чужих данных и извлечение секретов запрещены;
- intrusive-техники только lab-only или после отдельного письменного approval;
- если действие неоднозначно, статус `requires approval`.

## 11. Требования к стилю

Стиль лекций:

- профессиональный, но понятный новичку;
- без “воды” и мотивационных заглушек вместо знаний;
- без необъясненных терминов;
- без списков инструментов без контекста;
- с постепенным ростом сложности;
- с явной связью “концепция -> пример -> практика -> evidence -> критерий сдачи”.

Недопустимо:

- превращать урок в оглавление;
- заменять теорию ссылками;
- давать практику до объяснения нужных понятий;
- смешивать macOS и Kali-команды без пометки;
- давать потенциально опасные команды для Slider AI без scope/approval;
- считать урок готовым только потому, что валидатор нашел заголовки.

## 12. Критерий готовности лекции

Лекция считается готовой, если студент может:

1. Прочитать только Markdown-файл урока и понять тему без внешнего поиска.
2. Объяснить ключевую модель своими словами.
3. Выполнить обязательный безопасный путь новичка.
4. Получить и интерпретировать эталонный вывод.
5. Сдать sanitized evidence по rubric.
6. Понять, что запрещено на Slider AI и почему.
7. Назвать, какие знания понадобятся в следующих уроках.

Если хотя бы один пункт не выполняется, урок считается не самодостаточной лекцией, а заготовкой.
