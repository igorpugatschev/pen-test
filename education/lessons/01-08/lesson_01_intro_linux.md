# Занятие 1: Введение в Linux для пентестера

## Учебная рамка

**Входные требования:** Уверенное выполнение команд из предыдущих занятий; доступ к терминалу macOS/Linux или учебной VM.

**Результат занятия:** Студент выполняет базовую операцию Linux, объясняет назначение команд и фиксирует результат в заметках.

**Наследуемая SDET-компетенция:** профессиональная рабочая среда, evidence workspace, терминальная дисциплина и воспроизводимые команды.

**Security QA-компетенция:** подготовка безопасной рабочей станции и локального evidence-контура.

**Связь с книгами:** «PyCharm. Профессиональная работа на Python 2024» — terminal, Git, Markdown evidence и рабочая станция; SDET-курс — IDE/venv/terminal discipline.

**Процессный артефакт:** `SECURITY_TEST_STRATEGY.md` или `EVIDENCE_POLICY.md`: заметка о рабочей среде и правилах evidence.

**Безопасная цель:** Локальная домашняя директория студента, специально созданная папка `~/pentest-lab`, учебная VM Kali/Ubuntu только для углубления. Не использовать чужие системы.

**Среда выполнения:** Основной путь новичка — терминал macOS и локальная папка `~/pentest-lab`. Kali Linux ARM64 VM в UTM — углубление после освоения базовой навигации.

**Обязательный путь новичка:** Повторить команды из урока на локальных файлах, записать 3-5 наблюдений и сохранить вывод ключевых команд.

**Углубление:** Выполнить дополнительное задание в отдельной VM, сравнить поведение Linux и macOS, оформить короткий troubleshooting-разбор.

**Минимальная проверка успеха:** Команды из практики выполнены без ошибок, создан ожидаемый файл/каталог/вывод, студент может повторить действие по памяти.

**Эталонный вывод:** В отчете есть команда, ожидаемый вывод терминала и короткое объяснение, что этот вывод подтверждает.

**Критерии сдачи:** Зачет: выполнен обязательный путь, приложен вывод, нет действий вне учебной среды. Отлично: выполнено углубление и описана одна типичная ошибка.

## Теория

Linux часто используется в пентесте, а Kali Linux включает готовый набор инструментов для тестирования на проникновение. В этом курсе MacBook Air M2 остается рабочей станцией QA: базовые навыки терминала сначала отрабатываются на macOS, а Kali Linux подключается как отдельная лабораторная среда, когда это действительно нужно.

### Основные понятия

**Дистрибутивы Linux:**
- Kali Linux — специализированный дистрибутив для пентеста (основан на Debian)
- Parrot Security — альтернатива Kali с акцентом на приватность
- Ubuntu/Debian — для общего использования и серверов

**Файловая система Linux:**
- Все начинается с корня `/`
- Нет дисков C:, D: — всё в едином дереве
- Регистр имеет значение: `File.txt` и `file.txt` — разные файлы

**Ключевые директории:**
- `/etc` — конфигурационные файлы системы и служб
- `/var` — изменяемые данные (логи, кэш, почта, базы данных)
- `/home` — домашние директории пользователей
- `/root` — домашняя директория суперпользователя
- `/bin`, `/usr/bin` — исполняемые файлы программ
- `/tmp` — временные файлы (часто слабые права доступа)
- `/proc`, `/sys` — виртуальные файловые системы (информация о процессах и ядре)

**Виртуализация:**
- VMware Workstation / VMware Fusion
- VirtualBox (бесплатный, но на Mac с процессором M2 рекомендуется использовать **UTM** или **Parallels Desktop** для лучшей производительности)
- Прямой запуск на железе или в облаке

> **Примечание для пользователей macOS (M2, 8GB RAM):** При запуске виртуальных машин Kali Linux на Mac с 8GB оперативной памяти, выделяйте виртуалке не более **3-4GB RAM**, чтобы система не тормозила.

## Практическое занятие

### Шаг 1: Подготовка рабочей папки на macOS

1. Откройте Terminal на macOS.
2. Создайте локальную учебную папку:
   ```bash
   mkdir -p ~/pentest-lab/{notes,evidence,scripts,tmp}
   cd ~/pentest-lab
   pwd
   ```
3. Зафиксируйте в заметках, что это учебная локальная среда, а не цель тестирования.

### Углубление: Kali Linux ARM64 VM

Kali VM не обязательна для первого занятия. Если нужна отдельная Linux-среда:
1. Используйте Kali Linux ARM64 ISO/образ.
2. Запускайте VM через UTM, VMware Fusion или Parallels.
3. Выделяйте 2 CPU, 3-4GB RAM и 20-40GB диска.
4. Сделайте snapshot чистой системы после установки.
5. Не используйте x86/x64 Kali VM как стандартный путь на Apple Silicon.

### Шаг 2: Первичная настройка

```bash
# Для macOS (основной путь):
brew update && brew upgrade
brew install vim curl wget git

# Для Kali Linux ARM64 VM (углубление):
sudo apt update && sudo apt full-upgrade -y
sudo apt install -y vim curl wget git

# Проверка версии Kali (только в VM)
cat /etc/os-release
```
**Пример вывода `cat /etc/os-release`:**
```text
PRETTY_NAME="Kali GNU/Linux Rolling"
NAME="Kali GNU/Linux"
ID=kali
VERSION="2024.1"
VERSION_ID="2024.1"
ID_LIKE=debian
```

### Шаг 3: Изучение файловой системы

```bash
# Перейти в корень и посмотреть структуру
```

### Шаг 4: Навигация по файловой системе

```bash
# Где я сейчас?
pwd

# Перейти в домашнюю директорию
cd ~
pwd

# Перейти в /etc

pwd

# Вернуться назад
cd ..
pwd

# Перейти в домашнюю директорию пользователя root

# (если нет прав, используйте sudo -i)
```

## Адаптация под macOS (M2, 8GB)

- Для macOS native используйте Homebrew или официальный installer: `brew install <tool>`; для явно помеченной Kali/Linux-среды допустим `apt`.
- Kali/Linux VM запускайте только как углубление и выделяйте не более 3-4GB RAM на MacBook Air M2 (8GB)
- Если нужна Kali/Linux VM на Apple Silicon, используйте ARM64-образ в UTM/VMware Fusion/Parallels; не используйте x86/x64 VM как базовый путь.
- Docker работает нативно на M2: `docker pull <image>`
- Для VPN используйте Tunnelblick (OpenVPN) или официальные клиенты
- Для Python используйте `pip3 install` вместо `pip install`


## Задачи для самостоятельного выполнения

1. **Минимум:** Создайте `~/pentest-lab/{notes,evidence,scripts,tmp}` на macOS, сохраните вывод `pwd` и `ls -la` в `notes/lesson_01.md`.

2. **Углубление:** Установите Kali Linux ARM64 в UTM/VMware Fusion/Parallels и создайте snapshot чистой системы. Не используйте x86/x64 VM как базовый путь на M2.

3. Изучите содержимое директории `/etc` в Kali/Ubuntu VM или сравните с `/etc` на macOS. Найдите файлы: `passwd`, `group`, `hosts`, `resolv.conf` если они есть в выбранной среде. Опишите назначение каждого файла в `etc_files.txt`.

4. Создайте структуру директорий в своем домашнем каталоге:
   ```
   ~/pen-test/
   ├── targets/
   ├── tools/
   ├── reports/
   └── scripts/
   ```
   Используйте команду `mkdir -p` для создания вложенных директорий.

5. *(Перенесено в Урок 6: Поиск файлов)*.
   *Справка:* Для поиска файлов по времени изменения используется команда `find`. Мы изучим её подробно в Уроке 6. Пока просто изучите содержимое `/var/log/` через `ls -lt`.

6. Выведите полный путь к исполняемому файлу команды `python3` с помощью `which python3`. Если `whereis` недоступен или ведет себя иначе на macOS, отметьте это как различие среды.

## Частые ошибки

1. **Путаница с регистром.** В Linux `File.txt` и `file.txt` — это разные файлы. Всегда проверяйте регистр при вводе путей.
2. **Забытое обновление системы.** В Kali Linux выполняйте `sudo apt update && sudo apt full-upgrade -y`. В macOS — `brew update && brew upgrade`.
3. **Отсутствие снимков (snapshots) VM.** Перед экспериментами с пентестингом всегда делайте снимок виртуальной машины, чтобы можно было откатиться назад.
