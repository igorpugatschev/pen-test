## Теория

### 1. Терминал, shell и команда

Терминал — это окно, через которое вы общаетесь с shell. Shell — программа, которая читает команду, запускает нужный исполняемый файл или встроенное действие и возвращает вывод.

На macOS по умолчанию часто используется `zsh`. В Linux часто используется `bash`. Для базовых команд этого урока различия не критичны, но в сложных скриптах они важны.

Команда обычно состоит из четырех частей:

```text
command option argument redirection
```

Пример:

```bash
ls -la ~/slider-ai-pentest > evidence/lesson_02/file_list.txt
```

Разбор:

- `ls` — команда;
- `-la` — опции: подробный вывод и скрытые файлы;
- `~/slider-ai-pentest` — аргумент, то есть что показать;
- `>` — перенаправление вывода в файл.

### 2. Текущая директория

Большинство ошибок новичка начинается с того, что команда выполнена «не там». Shell всегда имеет текущую директорию. Ее нужно проверять командой:

```bash
pwd
```

Если вы находитесь в `~/slider-ai-pentest`, команда `touch notes/a.md` создаст файл в правильном workspace. Если вы в другой папке, файл уйдет туда. Поэтому правило урока: перед созданием, копированием, перемещением и особенно удалением сначала выполнить `pwd`.

### 3. Навигация: `cd`, `~`, `.`, `..`

```bash
cd ~/slider-ai-pentest
cd notes
cd ..
cd ./evidence
cd ~
```

Как читать:

- `~` — домашняя директория;
- `.` — текущая директория;
- `..` — директория уровнем выше;
- `./evidence` — папка `evidence` внутри текущей директории.

Для Security QA это важно при работе с evidence: вы должны понимать, где лежит скриншот, где заметка, где временный файл, а где файл, который можно приложить к отчету.

### 4. Просмотр файлов: `ls`

`ls` показывает содержимое директории.

Основные варианты:

| Команда | Что показывает | Когда использовать |
|---|---|---|
| `ls` | имена файлов | быстро посмотреть папку |
| `ls -l` | подробный список | увидеть права, владельца, размер, дату |
| `ls -a` | включая скрытые файлы | проверить `.env`, `.gitignore`, `.zshrc` локально |
| `ls -lah` | подробно, скрытые, читаемые размеры | основной удобный вариант |
| `ls -lt` | сортировка по времени | найти свежий evidence |

Скрытые файлы начинаются с точки. Это не значит, что они секретные. Это значит, что обычный `ls` их не показывает.

### 5. Создание папок и файлов: `mkdir`, `touch`, `echo`, `cat`

`mkdir` создает директорию:

```bash
mkdir evidence/lesson_02
```

Если нужно создать цепочку папок, используется `-p`:

```bash
mkdir -p evidence/lesson_02/raw
```

`touch` создает пустой файл или обновляет время изменения:

```bash
touch evidence/lesson_02/commands.txt
```

`echo` выводит строку:

```bash
echo "Lesson 02 terminal practice"
```

Если направить `echo` в файл, получится простая запись:

```bash
echo "Lesson 02 terminal practice" > evidence/lesson_02/commands.txt
```

`cat` выводит содержимое файла. В книге «Легкий способ выучить Python 3 еще глубже» команда `cat` используется как маленькое упражнение для понимания командной строки: вход — файл, действие — прочитать, результат — текст на экране. В Security QA эта же идея используется постоянно: прочитать лог, проверить сохраненный запрос, показать фрагмент evidence.

### 6. Перенаправление: `>` и `>>`

`>` записывает вывод в файл с перезаписью.

```bash
pwd > evidence/lesson_02/location.txt
```

Если файл уже существовал, старое содержимое будет заменено.

`>>` добавляет вывод в конец файла.

```bash
whoami >> evidence/lesson_02/location.txt
```

Правило безопасности: если файл содержит evidence, чаще используйте `>>`, чтобы случайно не потерять предыдущие строки. Перед `>` спросите себя: «Я точно хочу перезаписать файл?»

### 7. Пайп: `|`

Пайп передает вывод одной команды на вход другой.

```bash
ls -la ~/slider-ai-pentest | grep notes
```

Разбор:

- `ls -la` создает список;
- `|` передает список дальше;
- `grep notes` оставляет строки, где есть `notes`.

В Security QA пайпы помогают быстро фильтровать логи и вывод инструментов. Но в ранних уроках мы используем их только на локальных файлах.

### 8. Просмотр больших файлов: `less`, `head`, `tail`

`cat` хорош для маленьких файлов. Для большого файла удобнее:

```bash
less file.txt
head -5 file.txt
tail -5 file.txt
```

`less` открывает постраничный просмотр. Внутри:

- `q` — выйти;
- `/text` — найти текст;
- `n` — следующий результат поиска.

`head` показывает начало файла, `tail` — конец. Логи часто читаются с конца, потому что новые события добавляются вниз.

### 9. Поиск текста: `grep`

`grep` ищет строки по шаблону:

```bash
grep "Status" notes/lesson_01.md
```

Для нескольких файлов:

```bash
grep -R "requires approval" notes
```

На раннем этапе важно не усложнять регулярными выражениями. Сначала научитесь отвечать на простой вопрос: «В каких моих заметках встречается этот статус?»

### 10. Подсчет и сортировка: `wc`, `sort`, `uniq`

`wc` считает строки, слова и байты:

```bash
wc -l evidence/lesson_02/commands.txt
```

`sort` сортирует строки:

```bash
sort evidence/lesson_02/commands.txt
```

`uniq` убирает соседние дубликаты, поэтому часто используется после `sort`:

```bash
sort evidence/lesson_02/commands.txt | uniq
```

Эти команды пригодятся позже для анализа списков URL, заголовков, параметров и повторяющихся наблюдений.

### 11. Осторожно с `rm`, `mv` и перезаписью

`rm` удаляет файлы. В курсе мы не начинаем с агрессивного `rm -rf`, потому что новичку важнее сформировать безопасную привычку.

Безопаснее:

```bash
rm -i tmp/test.txt
```

`-i` спрашивает подтверждение.

Перед удалением:

1. Выполните `pwd`.
2. Выполните `ls -la`.
3. Проверьте, что файл находится в `tmp` или другой безопасной учебной папке.
4. Используйте `rm -i`.

`mv` может переместить файл или переименовать его. Это удобно, но можно случайно затереть существующий файл. Поэтому перед `mv` проверяйте, существует ли целевой путь.

## Практическое занятие

### Шаг 1: Подготовить папку урока

```bash
cd ~/slider-ai-pentest
mkdir -p evidence/lesson_02
touch notes/lesson_02_terminal.md
pwd
```

Пример вывода:

```text
/Users/student/slider-ai-pentest
```

### Шаг 2: Сохранить базовую информацию о среде

```bash
{
  echo "# Lesson 02 — Terminal evidence"
  echo
  echo "Environment: macOS native"
  echo "Target: local workspace only"
  echo
  echo "## Commands"
  echo
  echo '```text'
  pwd
  uname -m
  whoami
  echo '```'
} > notes/lesson_02_terminal.md
```

Пояснение: фигурные скобки группируют несколько команд, а `>` записывает общий вывод в файл. Это локальная операция, она не обращается к Slider AI.

### Шаг 3: Создать учебные файлы

```bash
cd ~/slider-ai-pentest/evidence/lesson_02
touch report1.txt report2.txt report3.txt
echo "Status: observation" > report1.txt
echo "Status: not applicable" > report2.txt
echo "Status: requires approval" > report3.txt
ls -lah
```

Пример вывода:

```text
total 24
drwxr-xr-x  5 student  staff  160 May 22 10:20 .
drwxr-xr-x  3 student  staff   96 May 22 10:20 ..
-rw-r--r--  1 student  staff   20 May 22 10:20 report1.txt
-rw-r--r--  1 student  staff   24 May 22 10:20 report2.txt
-rw-r--r--  1 student  staff   26 May 22 10:20 report3.txt
```

Что это подтверждает: файлы созданы в правильной папке, у них есть обычные пользовательские права, работа идет локально.

### Шаг 4: Читать файлы

```bash
cat report1.txt
cat -n report2.txt
head -1 report3.txt
```

Пример вывода:

```text
Status: observation
     1	Status: not applicable
Status: requires approval
```

Что это подтверждает: студент умеет читать маленькие evidence-файлы и видеть содержимое без редактора.

### Шаг 5: Копировать и перемещать

```bash
mkdir archive
cp report1.txt archive/report1.copy.txt
mv report2.txt archive/report2.moved.txt
ls -lah
ls -lah archive
```

Как читать результат:

- `report1.txt` должен остаться на месте, потому что `cp` копирует;
- `report2.txt` должен исчезнуть из текущей папки и появиться в `archive`, потому что `mv` перемещает;
- новое имя `report2.moved.txt` показывает, что `mv` также умеет переименовывать.

### Шаг 6: Фильтровать вывод

```bash
grep -R "Status" .
grep -R "requires approval" .
```

Пример вывода:

```text
./report1.txt:Status: observation
./report3.txt:Status: requires approval
./archive/report1.copy.txt:Status: observation
./archive/report2.moved.txt:Status: not applicable
./report3.txt:Status: requires approval
```

Что это подтверждает: `grep -R` ищет по текущей папке и подпапкам. Это удобно для заметок, но на реальном продукте нельзя бездумно искать и сохранять секреты.

### Шаг 7: Добавить результат в заметку

```bash
{
  echo
  echo "## Evidence summary"
  echo
  echo '```text'
  ls -lah ~/slider-ai-pentest/evidence/lesson_02
  echo '```'
  echo
  echo "Interpretation: local evidence files were created, read, copied and moved safely."
  echo "Result status: observation"
} >> ~/slider-ai-pentest/notes/lesson_02_terminal.md
```

Обратите внимание на `>>`: мы добавляем новый блок в конец заметки, а не перезаписываем уже записанную информацию.

### Шаг 8: Безопасное удаление только временного файла

```bash
cd ~/slider-ai-pentest/evidence/lesson_02
touch tmp-delete-me.txt
pwd
ls -lah tmp-delete-me.txt
rm -i tmp-delete-me.txt
```

Если shell спросит подтверждение, введите `y` только после проверки пути и имени файла.

## Адаптация под macOS (M2, 8GB)

- На macOS используйте Terminal и `zsh`; для этого урока не нужна Kali VM.
- Часть флагов Linux-команд может отличаться на macOS, потому что многие системные утилиты имеют BSD-варианты.
- Если команда из Linux-примера не совпадает, фиксируйте это как troubleshooting-наблюдение, а не как провал.
- Не устанавливайте GNU-версии команд только ради первых уроков.
- Kali ARM64 VM используйте позже для Linux-специфичных упражнений, ограничив RAM до 3-4GB.

## Частые ошибки

1. **Выполнить команду не в той папке.** Лечится привычкой `pwd` перед важным действием.
2. **Перезаписать evidence через `>`.** Для добавления используйте `>>`.
3. **Думать, что `mv` только перемещает.** `mv` также переименовывает и может затереть целевой файл.
4. **Открывать большой файл через `cat`.** Для больших файлов используйте `less`, `head`, `tail`.
5. **Использовать `rm -rf` как привычку.** В учебном курсе сначала используется `rm -i` и только локальные временные файлы.

**Ограничения безопасности:** соблюдать `education/slider_ai_scope.md`; не выполнять DoS/load-тесты, brute force, destructive payloads, изменение чужих данных, извлечение секретов и действия вне согласованного scope.

**Уровень прогрессии:** локальная подготовка evidence без обращения к приложению.

### Минимум

Создайте файл `notes/lesson_02_terminal.md`, добавьте дату, локальную среду, цель стенда и список будущих типов артефактов.

### Практика Slider AI

Создайте локальный файл:

```bash
cd ~/slider-ai-pentest
echo "Allowed target: https://olddev.slider-ai.ru; no product testing in lesson 02" > requests/slider_ai_scope_note.txt
cat requests/slider_ai_scope_note.txt
```

Это не проверка сайта. Это подготовка локальной дисциплины: URL стенда записан, границы понятны, никаких запросов к приложению не выполняется.

### Углубление после изучения следующих уроков

После урока 6 добавьте поиск по заметкам и быстрый список всех файлов доказательств:
