• Функция bubble_sort вызывается один раз, но merge_node вы­
зывается 1599 раз, a merge еще больше - 7500 раз. Это связано с тем,
что функции merge_node и merge являются рекурсивными, поэто­
му, сортируя случайный список из 8оо элементов, они будут произво­
дить огромное количество вызовов.
• Несмотря на то что bubble_sort вызывается гораздо меньше, чем
merge или merge_node, она намного медленнее. Это соответству­
ет ожиданиям производительности двух алгоритмов. Наихудший
случай для сортировки слиянием - О (n log п), но для пузырь­
ковой сортировки это О (п А 2). Если у вас 8оо элементов, значит,
800 log 8 00 составляет около 5347, тогда как 800 А 2 равно
640 ооо! Эти числа не обязательно указывают на точное число се­
кунд, за которое выполняются алгоритмы, но их можно использовать
для относительного сравнения.
• Функция count вызывается 799 раз, что, скорее всего, значительная
трата времени. Наша реализация двусвязного списка не отслежива­
ет количество элементов, вместо этого выполняя проход по списку
каждый раз, когда вы хотите узнать это количество. Мы используем
тот же метод в функции count здесь, и это приводит к 799 прохо­
дам по всему списку из 8оо элементов. Замените max_numbers на
боо или 500, чтобы увидеть закономерность. Обратили внимание,
что count выполняется п-1 раз? Это значит, что мы проходим поч­
ти все 8оо элементов.
